# 数据挖掘实验 —— 景区游览指南的程序性知识挖掘

课程实验成果汇总。七个实验由三名成员分工完成，最终串成一条链路：
网页采集与预处理 → 实体识别 → 路线层级结构 / 共指消解 / 条件建议抽取 → 知识图谱 → 旅游规划 Agent。

> **接手先看**：[`实验7-旅游规划Agent/交接说明.md`](实验7-旅游规划Agent/交接说明.md) —— 怎么配自己的模型参数、怎么跑起来、常见问题。

## 目录

| 目录 | 内容 |
|---|---|
| `实验1-数据采集与预处理/` | 三个景区（故宫博物院、颐和园、天坛公园）官方与游记网页的采集、清洗，产出 `documents.csv` |
| `实验2-实体识别/` | 基于词典与规则的中文实体识别，产出 `entities.json`（POI / TIME / TRANSPORT） |
| `实验3-路线层级结构/` | 从游记与官方线路中抽取游览路线，还原"景区 → 路线 → 步骤"层级 |
| `实验4-程序性知识共指消解/` | 指代与省略消解，把"它""这里"等回指绑定到具体景点 |
| `实验5-条件性游览建议/` | 抽取"如果……就……"形式的条件建议（时间、人群、天气等条件） |
| `实验6-知识图谱/` | 多源融合建图，产出 `nodes.csv` / `edges.csv` 与三种可视化，含 Neo4j 导入脚本 |
| `实验7-旅游规划Agent/` | 基于图谱的 ReAct 旅游规划 Agent，四个图谱查询工具 + 路线规划器 + LLM 集成 |

## 环境

- Python 3.11（Anaconda）
- 实验 1~5：`pandas`、`requests`、`beautifulsoup4`、`jieba`
- 实验 6：`networkx`、`matplotlib`、`pyvis`
- 实验 7：仅标准库 + `requests`（LLM 走 OpenAI 兼容接口）

## 运行顺序

```bash
# 实验 6：归一化建图 → 建图校验与可视化
python 实验6-知识图谱/代码/02_normalize_nodes.py
python 实验6-知识图谱/代码/03_build_graph.py

# 实验 7：规则后端跑测试场景
cd 实验7-旅游规划Agent/代码 && python run_scenarios.py

# 实验 7：接入真实模型（需要 API key）
export LLM_API_KEY=...   # 或写进 代码/llm_config.local.json，见交接说明.md
python run_scenarios.py --real-llm
```

实验 6 与 7 的脚本通过"向上查找名为 `实验资料整理` 的目录"定位项目根目录，
因此**本目录不能改名**。
