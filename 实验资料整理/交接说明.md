## 1. 配置自己的模型参数（重点）

### 1.1 放哪里

仓库里已经放好了模板 **`代码/llm_config.example.json`**，最省事的做法是复制一份、改名、填自己的值：

```bash
cd 实验7-旅游规划Agent/代码
cp llm_config.example.json llm_config.local.json   # Windows: copy llm_config.example.json llm_config.local.json
# 然后编辑 llm_config.local.json
```

文件名必须是 **`llm_config.local.json`**，和 `llm.py` 同级。整个文件长这样：

```json
{
  "LLM_API_KEY": "sk-你自己的key",
  "LLM_BASE_URL": "https://api.deepseek.com/v1",
  "LLM_MODEL": "deepseek-flash"
}
```

三个字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `LLM_API_KEY` | ✅ | 你的 key。不填这个，程序会自动走规则后端 |
| `LLM_BASE_URL` | ❌ | OpenAI 兼容地址，默认 `https://api.deepseek.com/v1` |
| `LLM_MODEL` | ❌ | 模型名，默认 `deepseek-flash`（服务端显示名 DeepSeek-V4.1-Flash） |

> **没改的占位符会被自动忽略**：如果 `LLM_API_KEY` 还是"你的api""sk-你自己的key"这种模板文字，
> 程序会当成"没配置"直接走规则后端，不会拿着假 key 去请求、也不会报一堆 401。
> `base_url` 填的不是 `http` 开头、`model` 含中文，也会自动退回默认值。

### 1.2 这个文件不会进 git

`.gitignore` 里已经写了两条规则：

```
**/llm_config.local.json
**/llm.local.json
```

所以**每个人的 key 各填各的、互不覆盖、也不会被提交**。改完 `git status` 看不到它，这是正常的。

验证一下被忽略：

```bash
git check-ignore -v 实验7-旅游规划Agent/代码/llm_config.local.json
# 会输出 .gitignore:46:**/llm_config.local.json ...
```

### 1.3 换别的模型服务商

任何 OpenAI 兼容服务都行，代码不用改，只改这两行：

```json
{
  "LLM_API_KEY": "sk-xxx",
  "LLM_BASE_URL": "https://dashscope.aliyuncs.com/compatible-mode/v1",
  "LLM_MODEL": "qwen-plus"
}
```

常见地址：通义千问 `https://dashscope.aliyuncs.com/compatible-mode/v1`，
Kimi `https://api.moonshot.cn/v1`，本地 vLLM `http://localhost:8000/v1`。

### 1.4 也可以用环境变量（优先级更高）

不想建文件就设环境变量，效果一样：

```powershell
# Windows PowerShell
$env:LLM_API_KEY = "sk-你自己的key"
$env:LLM_MODEL   = "deepseek-flash"
```

```bash
# macOS / Linux
export LLM_API_KEY="sk-你自己的key"
export LLM_MODEL="deepseek-flash"
```

也认常见别名：`DEEPSEEK_API_KEY` / `OPENAI_API_KEY` / `OPENAI_BASE_URL` / `OPENAI_MODEL`。

### 1.5 查找顺序（四级）

```
环境变量（主名 + 别名）
    ↓ 没有
代码目录 llm_config.local.json
    ↓ 没有
~/.dsh/secrets/llm.local.json
    ↓ 没有
内置默认值（base_url / model 有默认，key 没有）
```

**规则**：环境变量整体优先于本地文件。所以想临时换个 key 试一下，
直接 `$env:LLM_API_KEY="sk-另一个"` 就行，不用动文件。

### 1.6 想看配置到底读到没有

```bash
cd 实验7-旅游规划Agent/代码
python llm.py
```

正常输出（key 只显示掩码，不会打印全文）：

```json
{
  "available": true,
  "model": "deepseek-flash",
  "base_url": "https://api.deepseek.com/v1",
  "api_key_set": true,
  "api_key_masked": "sk-c6e…1dcb",
  "calls": 0

```

`"available": false` 就是没读到 key，检查文件名和 JSON 格式（逗号、引号）。

## 5. 常见问题

**Q1：`ModuleNotFoundError: No module named 'kg_tools'`**
工作目录不对。`cd` 到 `实验7-旅游规划Agent/代码` 再跑。别用 VS Code 右上角的"运行"按钮（它用文件所在目录当 cwd 之外的路径）。

**Q2：一直是规则后端，`available: false`**
三种可能：① 没建 `llm_config.local.json` ② 文件名拼错（必须是 `.local.json`）③ JSON 格式坏了。
跑 `python llm.py` 看 `api_key_set`。坏 JSON 不会报错，只会静默降级为规则后端。

**Q3：报 401 / 403**
key 无效或过期。换一个再试，`llm.py` 不缓存失败结果。

**Q4：把 `实验资料整理` 改名了，全都跑不动**
改回去。6 个脚本靠这个名字定位根目录。

**Q5：`git status` 里看不到 `llm_config.local.json`**
正常，被 `.gitignore` 忽略了。这是故意的。

**Q6：报告里的时间准吗**
不准，是估算的。实验 3 上游给出的 `time_slot` / `duration_min` 全是空的，
所以 Agent 用"每景点 6 分钟 + 转场 3 分钟"的口径估算，回答里也会显式说明"这不是实测"。

## 6. 已知边界

1. 图谱只覆盖三个景区：**故宫博物院、颐和园、天坛公园**。问别的景区会明确说查不到。
2. 条件建议只有 **3 条**，全在故宫，且 `audience` 全部是"通用"，没有老人/亲子等标签——Agent 回答里会讲明这一点，不假装有。
3. 路线时长、时段（上午/下午）在上游是空的，图里也没有 `TimeSlot` 节点。
4. 游记路线 `RT-YHY-VIS-001` 是三条官方线路被合并成一条的产物，已在图谱里标记 `quality_flag=segmentation_suspect`。
5. 真实模型的分支需要 key，没有 key 的机器上只能复现规则后端（这是设计如此，不是缺陷）。
