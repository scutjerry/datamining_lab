# B 结果适配说明（C 侧，2026-11-16）

本目录是成员C把成员B的实验3/4/5结果**重跑并转换**为组内接口约定格式后的产物。核心结论：**格式转换可以机械完成，但 B 的规则在 A 的真实长文本上质量不达标，需要 B 返工**。以下是具体过程和证据。

## 一、做了什么（三步）

1. **数据转换**（`convert_input.py`）：把 A 的 `documents.csv` + `provenance.json` 转成 B 管线输入格式 `cleaned_data.jsonl`（21 条，字段映射：`record_id←doc_id`、`attraction←scenic`、`text_type←official_route/traveler_note`），并用 A 的 `entities.json` 重新生成 POI 词典（212 词）。
2. **重跑 B 的管线**：在真实数据上运行 `python -m src.exp3_routes / exp4_coref / exp5_conditions`。三个实验均跑通、跨度校验全部通过；结果分别归档在实验3/4/5 的 `结果-真实数据/`。注意：实验5 需先清空 B 的复核候选样本（`condition_review_candidates.json`，原文件为生成语料专用，已备份为 `*_原生成语料备份.json`），否则校验报错。
3. **格式适配**（`adapt_contract.py`）：按接口约定输出 `routes.json`（官方路线结构）和 `advices.json`（条件建议），并把 B 的原始输出做机械转换留档对照。

## 二、产出与质量

| 文件 | 内容 | 质量 |
|---|---|---|
| `routes.json` | 19 条路线（官方 18 + 游客 1），250 个步骤，248 步命中 POI 词典 | **可用**。来自官方文本中的链式路线行（`A-B-C`、`A>>B>>C`）提取，颐和园 9 条入口路线还解析出了原文标注的时长（120/150/180 分钟） |
| `advices.json` | 3 条条件建议（均为"时间有限→精简路线"类，高置信） | **数量少但准**。取自 C 的兜底规则（`extraction: fallback_by_C`），B 的规则产出不可用 |
| `unparsed_official_docs.json` | D004（故宫官网导览）、D005（颐和园官网导览） | 无链式路线行，B 的提及级解析噪声大，暂不入图，需 B 补路线段切分 |
| `b_raw_mappings_converted.json` | B 的 48 条条件映射按约定字段机械转换 | **不建议入图**。抽查多为误报："两个桃尖→取意…""一天→先生所书" |
| `quality_report.json` | 全部质检统计 | — |

校验结果：19 条路线的 `source_doc_id`、3 条建议的 `source` 全部能在 A 的 21 个 `doc_id` 中命中；字段完整、步骤序号连续、枚举合法。`time_slot` 全部为 `null`（链式路线原文无时段，遵循"A 不补写时间"的原则）。

## 三、B 管线在真实文本上的三个失败点（写报告"失败现象"可用）

1. **粒度过细**：B 的解析器把文中每处 POI 提及都当作路线步骤，D001 一篇长文产出 131 步（含背景介绍里的"故宫又称紫禁城"），21 篇共 2776 步。生成语料是百字短文、POI 提及即路线，真实文本是几千字文章，必须先切出"路线段"再解析。
2. **条件规则全面误报**：51 条提及里人工抽查基本都不是"条件→建议"对（"不下马→它的面积比北京皇宫还要大十万平方米"）。原因是规则依赖生成语料常见的"如果/人多时+建议"模板句，真实游记的叙述句触发词密度完全不同。
3. **复核样本与新数据脱节**：B 的 12 条复核候选全部属于生成语料（迪士尼/西湖），换数据后校验直接报错；核心实验三/五不能直接重跑。

另外实验4（共指消解）本身能跑，1145 个代词提及、跨度校验通过，但 5 个先行词标注仍待 B 人工核验后才算有效结果。

## 四、对 B 的返工建议（发群里）

1. 实验3：在解析前加"路线段切分"（按"路线"标题/编号行/箭头链定位路线区，只解析路线区内的文本）；C 的链式提取逻辑可直接复用（见 `adapt_contract.py` 的 `extract_chains`）。
2. 实验5：条件触发词规则需按真实语料重定（已扫出 38 句含条件触发词的真实句子可作起点）；产出至少覆盖 weather/audience 两类才有统计意义。
3. 复核样本重建：在真实数据的输出里重新抽 12 条做人工复核；共指 5 个样本需本人核验后把 `annotation_source` 改为人工标注。
4. 输出字段按《给AB的输出格式说明》对齐（scenic/route_type/time_slot/poi_name/audience 等），或直接采用本目录的适配脚本。

## 五、复现

```bash
python3 -I convert_input.py          # A 数据 → B 输入（写入 B 项目 data/）
python3 -m src.exp3_routes           # 在 B 项目根目录运行
python3 -m src.exp4_coref
python3 -m src.exp5_conditions
python3 -I adapt_contract.py         # B 输出 → routes.json / advices.json
```

脚本中的路径是 C 本机临时路径，复现时按实际位置修改 `RUN` / `OUT` 常量。
